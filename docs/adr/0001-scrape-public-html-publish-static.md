# Acquire session data by scraping Sched's public HTML; publish as a static site

This is an unofficial, community project, so we have no organizer-issued Sched API key (keys are paid-plan and organizer-only). We therefore ingest each edition by scraping its **public** Sched schedule (`/list/simple` and `/list/descriptions`) rather than via the API, running a polite, idempotent, re-runnable pipeline (≤30 req/min, explicit User-Agent). The normalized output is stored as per-session JSON committed in the repo and rendered as a **static site** (Astro/11ty + Pagefind client-side search) on a free static host — chosen over a dynamic app + database because the corpus is small (~5 editions, low hundreds of sessions each) and changes only when the pipeline re-runs, so a server and database would add cost and upkeep for no benefit.
